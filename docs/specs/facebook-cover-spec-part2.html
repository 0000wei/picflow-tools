4. Canvas 渲染引擎技术详规

所有渲染由单一 Canvas 2D 上下文完成。使用双缓冲模式：内存 canvas（确保重绘不闪烁）+ 显示 canvas（仅用于事件派发）。或者单 canvas + requestAnimationFrame 重绘循环（更简单，推荐）。

4.1 渲染管线（每帧）

render() {
  1. clearRect(0, 0, 1200, 628) — 清空画布

  2. drawImage(img, offsetX, offsetY, imgWidth*scale, imgHeight*scale) — 绘制用户图片

  3. if (mode === 'safe') {
     3a. 绘制 3x3 网格（灰色细线，#ccc, 0.5px, 虚线？）
     3b. 绘制半透明黑色遮罩（fillRect 覆盖全面布，globalAlpha=0.55）
     3c. 裁掉安全区（clearRect(320, 155, 560, 312)）— 露出下面图片
     3d. 安全区边框（2px solid #6366F1，或动态的亮色）
     // 注：直接在遮罩上层 clearRect 是经典做法。或者用 globalCompositeOperation 做复杂蒙版。
     // 简单做法：先画三个矩形遮住非安全区（上、左、右、下四个矩形）
  }

  else if (mode === 'desktop') {
     3a. 绘制桌面端裁剪遮罩（上下遮挡矩形，露出 1200x312 水平带）
     3b. 绘制沉浸式 Facebook 桌面 UI（见第 5 节）
  }

  else if (mode === 'mobile') {
     3a. 绘制移动端裁剪遮罩（左右遮挡矩形，露出 560x628 垂直带）
     3b. 绘制沉浸式 Facebook 移动 UI（见第 5 节）
  }

  // 覆盖模式：画布实际显示区域可能小于 1200x628（比如 CSS 缩放了），
  // 但内部逻辑始终以 1200x628 为坐标系。
}

4.2 Canvas 尺寸与显示

  • 内部逻辑分辨率：1200 × 628 px（固定）
  • CSS 显示尺寸：响应式。max-width: 100%，高度自动。不拉伸失真。
  • HiDPI 适配：不需要。因为导出时才需要全分辨率。展示用小画布（600x314 CSS）显示大逻辑画布（1200x628），用 Canvas 的 CSS 缩放实现。
  • 推荐做法：Canvas 元素固定宽高为 1200×628 的 1/2（即 600×314），由 CSS 控制响应式。

4.3 3x3 网格

  • 只在 safe 模式下显示
  • 两条水平线：y = (628/3) × 1, y = (628/3) × 2
  • 两条垂直线：x = (1200/3) × 1, x = (1200/3) × 2
  • 颜色：rgba(255,255,255,0.3) 或 #ccc
  • 线宽：0.5px（Canvas 自动抗锯齿），或 1px 明线

4.4 遮罩层具体实现（safe 模式）

安全区是桌面可见区 ∩ 移动可见区 = (320, 155, 560, 312)。用四个半透明矩形覆盖非安全区域：

// 上：从 (0,0) 到 (1200, 155)
ctx.fillStyle = 'rgba(0,0,0,0.55)';
ctx.fillRect(0, 0, 1200, 155);

// 下：从 (0, 467) 到 (1200, 628)
ctx.fillRect(0, 467, 1200, 161);

// 左：从 (0, 155) 到 (320, 467)
ctx.fillRect(0, 155, 320, 312);

// 右：从 (880, 155) 到 (1200, 467)
ctx.fillRect(880, 155, 320, 312);

4.5 导出逻辑

function exportImage(format = 'png', quality = 0.92) {
  // 1. 创建导出用 canvas
  const exportCanvas = document.createElement('canvas');
  exportCanvas.width = 1200;  // 全分辨率
  exportCanvas.height = 628;

  // 2. 绘制用户图片（当前 offset/scale 参数）
  const ctx = exportCanvas.getContext('2d');
  ctx.drawImage(userImg, offsetX, offsetY, imgWidth * scale, imgHeight * scale);

  // 3. 不绘制遮罩层——导出的是"原始图片"在当前视口下的 1200x628 截图
  //   也就是说安全区遮罩、网格、UI 模拟层都不出现在导出中
  //   这一点对 UX 很重要：用户拖拽调整位置后，下载的是新裁切后的图片

  // 4. toBlob / toDataURL
  const mime = format === 'png' ? 'image/png' : 'image/jpeg';
  return new Promise(resolve => {
    exportCanvas.toBlob(blob => resolve(blob), mime, quality);
  });
}
关键 UX 决策：下载的图片不是"带有安全区遮罩层的预览图"，而是去掉所有遮罩/网格/UI模拟后、用户的图片在当前位置的 1200x628 完整截图。这样用户拖拽调整到安全区后，下载的就是一张完美的封面图。

5. 沉浸式 UI 模拟（B4 核心）

这是整个产品最重、最需要精雕细琢的部分。目标是让用户看到图片在真实 Facebook 页面上的样子。

5.1 桌面端沉浸式 UI

在 Canvas 上绘制的元素（在用户图片之上）：

  1. 裁剪框架：模拟桌面端只显示 1200x312 的水平带。上下区域用纯色（#0F0F11, 约 85% 黑）完全遮盖。
  2. 背景延伸：裁剪区域之外（上 155px 和下 161px）绘制接近 Facebook 的背景色（渐变或纯 #1B1B1F），模拟桌面页面继续往下滚动的感觉。
  3. 左下角头像：圆形，直径 80px。位置 (30, 628-90+30)。圆内显示假头像（生成一个渐变彩色圆）。头像下方或右侧显示"假名字"（如 Alex Johnson）。
  4. 底部操作按钮：渐变色条（从透明过渡到半透明黑），包含小圆的"👍 Like"、"💬 Comment"、"🔗 Share"图标+文字。位置在 (0, 628-40) 到 (1200, 628)。
  5. 顶部返回栏：位置 (0, 0) 到 (1200, 40)。半透明黑底 + "←" + "假名字" + "... 更多"。
  6. 照片指示器：右上角显示"相机"图标 + "Edit Cover Photo" 悬浮按钮。
设计原则：不需要像像素级复制 Facebook 界面，但要足够像，让用户产生"这就是我 Facebook 页面的效果"的感受。颜色取#1877F2 (Facebook 蓝) 和经典灰调。头像用渐变圆加"👤"或用户首字母。

5.2 移动端沉浸式 UI

Canvas 内部可视区变为 560×628（垂直带）。左右侧用纯色背景填充。

  1. 手机外框：不强制加手机外框（因为可能在电脑屏幕上预览），但可以在 canvas 整体外加一个圆角手机外形 CSS 效果。
  2. 顶部状态栏：(320, 0) 到 (879, 44) 位置。绘制时间（11:30）、信号格、电量图标。
  3. 导航栏：(320, 44) 到 (879, 88)。FB logo + "搜索" + "通知" 图标。
  4. 底部头像：圆形，直径 80px。位置 (320 + (560-80)/2, 628-90+30)。头像半重叠在封面上。
  5. 底部按钮行：(320, 628-60) 到 (879, 628)。渐变色条 + "👍 Like"、"💬 Comment"、"↗️ Share"。比桌面端更大。
  6. 返回按钮：左上角 "←"。
  7. 编辑/更多：右上角 "..."。
注意：移动端预览模式下，图片只有 560x628 的垂直带可见。左右各 320px 被 Facebook 自动裁掉。所以沉浸式的左/右侧要用纯色（模拟手机背景）填充。

6.3 事件绑定方式

  • HTML 中的元素使用 id 选择器，JS 中用 getElementById 引用（如 picete 现有风格）
  • 上传拖拽：uploadArea 的 dragover/dragleave/drop
  • 选择文件：fileInput.change
  • Ctrl+V：document.addEventListener('paste')
  • 模式切换：三个 radio 按钮或按钮组的 click 事件
  • 滑块：range input 的 input 事件
  • 格式选择：radiogroup 的 change 事件
  • 导出按钮：click

6.4 性能注意事项

  • Canvas 重绘使用 requestAnimationFrame 自动节流
  • 大图片（>4000px）加载后先缩放到最大 2000px 再渲染，节省 GPU 带宽
  • 沉浸式 UI 的绘制（头像、按钮、渐变条）在每帧重复，预渲染可以放在 offscreen canvas 上缓存
  • 不要同时在 canvas 上叠加多张高分辨率图片

6.5 语言切换

页面顶部有语言下拉框。JS 不需要处理多语言——JS 文件是所有语言共享的（picete 现有模式）。各语言的 HTML 页面引用同一个 js/facebook-cover.js。文本内容由 HTML 提供。
